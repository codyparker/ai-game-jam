# Skill UX Improvements — Design

## Changes

### 1. Remove model selection prompts

Remove setup questions 4 and 5 (designer/developer model). Remove all runtime detection logic (claude/codex/opencode). Setup flow becomes 4 questions: personality, theme, game type, complexity.

Task subagents inherit the parent model automatically (no `model` parameter passed). State.json drops `runtime`, `designerModel`, `developerModel` fields. Resume display no longer shows model info.

### 2. Rename folder to game name after completion

After Phase 6, the orchestrator:
1. Finds the game source subdirectory (not plans/, logs/, state.json)
2. Renames the top-level `YYYY-MM-DD-game/` to the game name (e.g., `gravity-hopper/`)
3. If target name exists, append suffix (`gravity-hopper-2/`)

Single `mv` via Bash. Update state.json paths accordingly.

### 3. Designer personality embodiment

Rewrite the designer system prompt so the personality is an identity, not a reference. Remove all hedging ("it's not a directive", "don't treat it as literal"). The designer should never mention "the prompt says" — they should BE the personality.

### 4. Stats.md at completion

Generated by the orchestrator after Phase 6. Contains:
- **The Story**: Narrative summary of collaboration.md
- **Timeline**: Per-phase wall-clock durations
- **Model**: Which model was used (inherited from session)
- **The Game**: Title, tech stack, file count, LOC
- **Design Evolution**: How the concept changed across rounds

Timing captured via `date +%s` Bash calls before/after each phase, stored in state.json `phaseTimings` field. File/LOC counts via Bash after build. Orchestrator writes stats.md directly (no subagent needed).
